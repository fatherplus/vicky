00 · 这本书是什么

为什么是这本书

Vicky 是一个个人知识平台：任何 AI agent 调研完一个技术，把内容 POST 过来，平台自动套用统一的「书」风格渲染、发布、归档，并经 L0–L3 蒸馏成可持续演化的知识 Wiki。这一页是它的 README——讲清它现在长什么样、每个决定背后的理由。

一句话立身：让 pi 适应你的工作流，而不是你去适应 pi——同理，让 agent 适应你的知识体系，而不是你适应 agent。视觉 taste 由 server 模板强制（agent 碰不到 CSS），内容 taste 由门禁强制，框内的画完全放开。

01 · 为什么是「书」

统一 taste，人读有书架，Agent 有 .md

不同 agent、不同时间写的报告风格五花八门，研究结论散落单篇、难以复用。解法是把所有报告收敛成同一本书的章节：宋体标题、黑体正文、等宽代码、纸墨配色，版式由 server 端模板强制——agent 只交内容，碰不到视觉。人读有书架（HTML），agent 消费给 .md 孪生（省 token 约 70%）。

层谁拥有为什么
视觉（配色/字体/版式）server 模板 + book-style.csstaste 不可被 agent 改坏
表述形态（裸表格/无结论对比）server 门禁形态不合格直接拒收
语义（词汇/叙事）表述规范 + 叙事宪法软约束，agent 自觉
框内的画（动效/图表/组件）agent 自由放开创造力
02 · 三分类骨架

research / brief / tech-solution，arch-doc 退场

报告按用途分三类，各走各的归宿：

research（技术文库）：调研沉淀，唯一进知识库蒸馏的分类。
brief（简报）：向上汇报、用完即弃，不进知识库。
tech-solution（技术方案）：讲「做什么/为什么」，归项目区聚合，其 .md 是给三方 agent 的实现契约。

arch-doc 为什么退场：架构不该是「一类报告」，而是项目的一个视图。旧的「丛书多卷」把架构拆成多篇文章靠 series 串联，点不动、改一处拉全部。现在架构 = 项目固有面板（交互式分层路由树），四分类顺势简化成三类。

03 · 项目空间

先建项目，架构是项目的固有面板

先建项目：project 把报告归入项目区，同一项目的 tech-solution 聚合在一起。架构导航器是项目的固有面板——进入即一张分层路由树（一/二/三层），模块是可点开的子文章、可被 agent 搜索；路由器是一等公民节点，出边带条件。骨架（arch_graphs）与模块正文（arch_modules）分家，各自增量读写——改结构不拉全文，改模块不动骨架。

04 · L0–L3 管线

每层产物可由下层再生

层职责存储
L0 原始提交快照（不可变档案）data/l0 + submissions 表
L1 表述门禁→模板→HTML+MD 孪生 + 索引/首页/项目页public/reports + reports 表

05 · Agent 怎么进来

Skill + 直连 HTTP，渐进式读写

不靠 MCP，靠 skill（vicky-writer）+ 直连 HTTP：agent 装好 skill，按 /api/guide 的规范写稿，POST 投稿；读知识走 knowledge_query。读写都是渐进式的——先看总览，再针对特定模块读/编辑，不一股脑拉全部。

内容方法论：先讲「为什么」再讲「是什么」；黄金结构（定位→痛点→为什么→方案→验证）不可颠倒；结论先行 + MECE；读者即上级——agent 的调研本质是向上汇报。

# 叙事方式选型库 —— 这一篇怎么讲

> 叙事方式（narrative）管**章节怎么组织**：切几章、按什么顺序展开、重点放在哪。
> 它是**章节组织指引，不是 HTML 模板文件**——不决定长什么样（视觉由 `book-style.css` 独占），
> 不决定去哪（归档由 `category` 决定）。同一套视觉皮肤，换一种讲法。
>
> 提交时用 `narrative` 字段显式指定；取值以 `GET /api/narratives` 返回的枚举为准。
> 叙事与骨架正交：同一个 `category` 下可以自由换叙事，同一篇里也可以局部借用
> （比如 tech-solution 正文用黄金五章、选型那一章用对比擂台）。

---

## 选型决策表

先问：**这篇内容的读者读完要获得什么？** 再按内容的核心特征对号入座：

| 内容特征 | 推荐叙事 | 典型 category |
|----------|----------|---------------|
| 要给结论、给建议，读者时间按秒计 | 金字塔 / 结论先行 | brief、research |
| 选型、方案 PK、多个候选要判决 | 对比擂台 | tech-solution、research |
| 复杂机制层层依赖，不拆开讲不透 | 问题拆解 | research、tech-solution |
| 算法 / 机制抽象难懂，需要跟例子走 | 场景演练 | research |
| 历程、演进、版本变化，讲"怎么变成这样的" | 时间线 / 演进 | arch-doc、research |
| 全局概览、多模块导航，读者要一张地图 | 总分总 / 地图 | arch-doc |
| 完整技术调研长文，没想清楚就默认它 | 黄金五章 | research |

判定口诀：**"为什么读" 用结论先行；"选谁" 用对比擂台；"怎么运作" 用问题拆解或场景演练；
"怎么变成这样" 用时间线；"从哪看起" 用地图；都不贴就黄金五章。**

---

## 1. 金字塔 / 结论先行

- **narrative 字段值**：`金字塔/结论先行`
- **最擅长讲什么**：要给结论和建议的文档——决策简报、评审材料、向上汇报。读者只读前 3 分钟就要拿到结论与推荐，依据与风险后置供查证。
- **章节骨骼（h2 序列）**：
  1. 结论与建议（TL;DR：结论 + 推荐 + 需要读者决定什么）
  2. 关键依据（支撑结论的证据，逐条，条条可查）
  3. 风险与例外（什么情况下结论不成立、代价是什么）
  4. 行动建议（给选择题：方案 A / B / C + 推荐）
- **适配骨架**：brief（天生）、research、tech-solution
- **推荐组件**：`blockquote` 挂结论、`data-table` 摆依据、`callout warn` 挂风险、`steps` 挂行动项
- **适用例子**：评估一次向量库选型——开篇三句话给出"选 A，理由三条、风险一条"，正文逐条展开依据与数据，结尾只留一个待拍板的决定。

## 2. 对比擂台

- **narrative 字段值**：`对比擂台`
- **最擅长讲什么**：选型、方案 PK。多个候选摆上擂台，先定判据再逐维过招，最后必须给出判决——"没有结论的对比就是没做完"。
- **章节骨骼（h2 序列）**：
  1. 参战选手（每个候选一句话定位 + 各自立场）
  2. 擂台维度（比什么、判据是什么，先声明）
  3. 逐维过招（每维度摆事实，不摆情绪）
  4. 判决（怎么选 · VERDICT：结论 + 例外条件）
- **适配骨架**：tech-solution（选型章节）、research（技术对比调研）
- **推荐组件**：`cmp-table`（核心，必带推荐列 + verdict）、`data-table`（补充原始数据）、`figure`（对比可视化）、`callout`（判决的例外）
- **适用例子**：pgvector / Milvus / Qdrant 三款向量库，先定"规模 / 召回 / 运维"三个维度，逐维对比后给出"按数据量级选"的判决，并说明各自适合的场景边界。

## 3. 问题拆解

- **narrative 字段值**：`问题拆解`
- **最擅长讲什么**：复杂技术层层剥开。大问题 → 拆成不重不漏的子问题 → 逐个解决 → 合起来看。读者面对难题时需要的不是答案，是"怎么拆"的路径。
- **章节骨骼（h2 序列）**：
  1. 大问题是什么（读者面临的难题，一句话说清）
  2. 拆解成子问题（MECE：互不重叠、合起来覆盖全部）
  3. 逐个攻破（每个子问题：解法 + 证据，可独立阅读）
  4. 合起来看（整体方案长什么样 + 仍存在的问题）
- **适配骨架**：research（复杂机制）、tech-solution（复杂方案）
- **推荐组件**：`steps` 挂拆解链、`figure` 挂问题树 / 依赖图（mermaid）、`data-table` 挂子问题清单、`callout` 挂遗留问题
- **适用例子**：讲"如何让个人知识库可被 agent 检索"——拆成入库、索引、检索、记忆四个子问题逐个解决，最后合起来讲整体链路，并明说哪个子问题还没做好。

## 4. 场景演练

- **narrative 字段值**：`场景演练`
- **最擅长讲什么**：算法、机制——抽象难懂，必须跟一个具体例子走。小数据集、逐步计算、类比，让读者"啊，原来是这么运作的"。
- **章节骨骼（h2 序列）**：
  1. 引入一个具体场景（小数据、有真实感，不造假数据）
  2. 逐步推演（手动算每一步，数字可复核）
  3. 提炼原理（从例子抽象出机制 / 公式）
  4. 迁移到自己场景（类比、变体、怎么调）
- **适配骨架**：research（算法 / 机制类首选）
- **推荐组件**：`steps`（推演步骤）、`data-table`（中间计算结果）、`figure` + mermaid（流程）、`pre`（示例代码 / 计算）
- **适用例子**：讲 RAG 的召回重排，用 5 条文档的小语料逐步走一遍打分计算，再抽象出打分公式，最后说明换语料、换权重怎么调。

## 5. 时间线 / 演进

- **narrative 字段值**：`时间线/演进`
- **最擅长讲什么**：历程、架构演进、项目进程、版本变化——回答"它怎么变成现在这样的"，让读者理解现状的来龙去脉。
- **章节骨骼（h2 序列）**：
  1. 起点（最初形态与动机）
  2. 阶段 1 → 阶段 2 → 阶段 3（每阶段：驱动因素 + 关键变化 + 付出的代价）
  3. 现状（当前形态与取舍）
  4. 趋势（往哪去、所以呢——图注的位置）
- **适配骨架**：arch-doc（演进章节）、research（技术演进调研）
- **推荐组件**：`figure`（时间线 / 阶段示意）、`data-table`（阶段对比：动机 / 变化 / 代价）、`blockquote`（关键决策的原话）、mermaid
- **适用例子**：讲一个项目从单体到微服务的演进——按"为什么拆 → 拆成什么样 → 付出什么代价 → 下一步往哪去"组织，每阶段都回答一次三问。

## 6. 总分总 / 地图

- **narrative 字段值**：`总分总/地图`
- **最擅长讲什么**：全局概览与导航。读者要的不是细节，是一张地图：系统是什么、有哪些模块、从哪开始读。
- **章节骨骼（h2 序列）**：
  1. 定位（这系统是什么、解决什么、不是什么）
  2. 全局图（一张总览图：mermaid / arch-flow）
  3. 模块索引（每个模块：一句话职责 + 链接，可点击跳转）
  4. 总（整体怎么配合、建议从哪读起）
- **适配骨架**：arch-doc（总览卷天生）、research（概览类调研）
- **推荐组件**：`arch-flow`（节点可点击跳各卷，首选）、mermaid（形状简单时）、`data-table`（模块索引：模块 / 职责 / 链接）、`figure` 装裱
- **适用例子**：项目架构总览卷——先定位项目，再一张全局流程图画清模块关系，随后模块索引表列出每卷链接；"总览 md 就是地图，AI 先读地图再钻节点卷"。

## 7. 黄金五章

- **narrative 字段值**：`黄金五章`
- **最擅长讲什么**：完整技术调研长文——研究一个技术、方案、开源项目，讲清"为什么"与"是什么"的默认讲法。
- **章节骨骼（h2 序列）**：
  1. 定位与边界（它是什么、不是什么）
  2. 场景与痛点（什么情况下遇到什么问题、不解决会怎样）
  3. 为什么是这套方案（每个决策必答三问）
  4. 方案与架构（整体怎么做）
  5. 细节与验证（机制 / 数据 / demo 证明真能解决）
- **适配骨架**：research（默认）、tech-solution
- **推荐组件**：全部按需——`cmp-table` 挂选型、`figure` 挂架构与验证、`steps` 挂场景演练、`data-table` 挂数据
- **适用例子**：调研一个新出现的向量数据库——先定位它与现有方案的区别与边界，讲清什么场景下值得用（痛点前置），再展开架构与实测数据验证结论。核心顺序不可颠倒：先让读者认同"问题存在且值得解决"，再给答案。

## 它不是模板文件

叙事方式是**章节组织指引**，不是 HTML 模板文件，也不是一套新的视觉皮肤：

- **不决定视觉**：字体、配色、版式、组件样式由平台强制（`BOOK-STYLE.md` 管像素、`EXPRESSION-GRAMMAR.md` 管表述形态）。叙事只是说"这一章讲什么、按什么顺序"，落在 HTML 里还是同一套 `<section class="reveal">` + 组件。
- **不决定归档**：进不进知识库、归不归项目区，由 `category` 决定（见 `AGENT-GUIDE.md`）。
- **不新增模板**：平台只维护这一个说明库，不维护 N 套模板。要新建模板仍走 `POST /api/templates`（rationale + narrative_contract，见宪法 `NARRATIVE-PRINCIPLES.md` §4）。
- **门禁不变**：裸 `<table>`、无结论的 `cmp-table` 等硬门禁与叙事无关，任何叙事下都适用。

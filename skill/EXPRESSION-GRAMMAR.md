# 表述规范 — 这本书的「内容语法」

> 本规范是宪法（NARRATIVE-PRINCIPLES.md）在「表述层」的展开：不变量管叙事顺序，本文件管同一内容全书怎么说。
> BOOK-STYLE.md 管**像素**（配色/字体/版式），本文件管**表述**（同一种内容在全书里怎么说）。
> 目标：读者跨报告建立阅读习惯——翻任何一篇都知道去哪找结论；同时不限制 agent 在框内发挥。

## 为什么需要它

视觉风格统一 ≠ 阅读体验统一。如果每篇报告的对比表长得不一样、结论放在不一样的地方、图表有的有标题有的没有，读者每篇都要重新学习"这篇怎么读"。

**习惯来自体例，不来自样式。** 就像 O'Reilly 或汉译世界学术名著：你不需要看内容就知道——对比章节末尾一定有"怎么选"，图下面一定有图题和图注。本规范定义的就是这套体例。

## 核心设计：三层约束

```
① 表述形态（语法）   封闭集 · server 强制      "这是什么类型的表述" → 唯一组件
② 语义词汇（语义）   全书统一 · 规则约束       颜色/字体/符号的含义固定
③ 自由区（发挥）     完全放开                  框里的画随便画
```

**固定"框"和"语义"，放开"框里的画"。** 这是统一与发挥的边界：agent 可以用任何图表库、任何交互形式，但必须套进书的"框"（组件 + 图题图注），用书的"词汇"（配色语义）。能力上限不被压低，因为限制的是装裱，不是画。

## 第一层：表述形态表（封闭集）

写任何内容前先自问：**这是哪种表述？** 答案必须是下表中的一种。表里没有的形态，用自由区（第三层）处理。

| 形态 | 组件 | 必答问题 | 固定收尾 | 硬约束 |
|------|------|----------|----------|--------|
| **陈列**（摆数据） | `<table class="data-table">` | 数据是什么 | 无 | 不许塞结论 |
| **对比**（选谁） | `<div class="cmp">` + `cmp-table` | 选谁？为什么？ | `怎么选 · VERDICT` | 必须推荐列 + 结论区，否则 server 拒收 |
| **图**（趋势/图表/截图/示意图） | `<figure class="figure">` | 这张图说明什么？ | 图注（so what） | 图题编号 + 图注必填；mermaid 图同样适用——`<pre class="mermaid">` 必须在 figure 内 |
| **论**（关键论断） | `<blockquote>` | 一句话立场 | 可选 `.attr` 出处 | — |
| **警**（注意/风险） | `<div class="callout note\|warn">` | 会出什么事、怎么办 | — | note=提醒，warn=风险，不许混用 |
| **序**（步骤/阶段） | `<div class="steps">` | 先做什么后做什么 | — | — |
| **列**（并列条目） | `<div class="card">` | 有哪几块 | — | — |
| **码**（代码） | `<pre>` | — | — | — |

### 形态判定规则

- 内容回答"**选谁**" → 对比，不许用 data-table，更不许裸 `<table>`
- 内容只是"**摆出来看**" → 陈列，不许在表里下结论（结论放表外的 callout 或正文）
- 任何**非表格的视觉内容**（折线、柱状、架构图、截图、交互 demo）→ 图，必须装裱

### 裸 `<table>` = 不合格

模板没有裸表格样式，裸表格会渲染成浏览器默认样子（无内边距、无字体、无线条），直接破坏全书观感。**server 会拒收带裸表格的内容。** 这不是建议，是门禁。

同理，**弃用组件类名也被拒收**：`.ladder-list/.ladder-rung/.ladder-num/.ladder-content`（→ `.steps`/`.step`/`.step-num`）、`.quote-block`（→ `blockquote`）、`.concern-box`（→ `.callout`）、`.phase`（→ `.steps`）。这些类已从模板删除，用了就裸奔——模板注释里标了 "已弃用" 的就是黑名单。

## 第二层：语义词汇（全书同义）

同一种颜色/字体/符号，在每篇报告里含义相同。读者学会一次，全书通用。

### 颜色语义

| 颜色 | 变量 | 含义 | 用在哪 |
|------|------|------|--------|
| 靛蓝 | `--accent` | 主线 / 推荐 / 正面强调 | 推荐列、图题、note 边条 |
| 朱砂 | `--seal` | 警告 / 风险 / 负面 | warn 边条、差值 `.r` |
| 绿 | `#2e7d32` | 好 / 胜 / 支持 | 对比优势 `.g`、正向数据 |
| 灰 | `--sub` | 中性 / 次要 | `.m`、图注、辅助说明 |

**自定义图表必须遵守同一语义**：推荐系列用靛蓝，负面数据用朱砂，不许为了"好看"反转含义。

### 字体角色

| 字体 | 角色 |
|------|------|
| 宋体 `--serif` | 标题、论断（blockquote）、编号——"书中郑重其事的话" |
| 黑体 `--sans` | 正文——默认叙述 |
| 等宽 `--mono` | 数据、代码、标签、图题编号、VERDICT 标记——"机器可读的部分" |

### 符号词汇

| 符号 | 含义 | 场景 |
|------|------|------|
| `✓` / `✗` | 支持 / 不支持 | 任何布尔对比（不止 cmp-table） |
| `.g` `.r` `.m` | 好 / 差 / 中性 | 任何三档评级 |
| `怎么选 · VERDICT` | 对比结论标记 | 一切回答"选谁"的内容末尾 |
| `图 N · 标题` | 图题 | 一切图的标题 |

### 固定收尾体例（习惯的来源）

- **对比必收尾**：回答"选谁"的内容，末尾必有 `怎么选 · VERDICT` 标记 + 结论。没有结论的对比不合格。
- **图必收尾**：每张图必有图题（`图 N · 标题`）+ 图注（一句话 so-what："所以呢？这说明……"）。只贴图不解释 = 不合格。
- **趋势必答走向**：趋势类内容（增长、演变、迁移）必须回答"往哪去、所以呢"，图注就是答案的位置。

## 第三层：自由区（发挥空间）

在 `.wrap` 内部，agent 可以做任何事：交互 demo、动画、自绘 SVG/Canvas、任意图表库。**能力上限不受限制。**

唯一的规矩：

1. **用书的词汇**：颜色走 CSS 变量和上面的语义，字体走三个变量。不许重定义 `:root` 变量。
2. **视觉内容要装裱**：自定义图表/示意图套进 `<figure class="figure">`，写图题图注。
3. **不碰页面框架**：书眉、丝带、tab 导航、页脚、藏书章。

自由区里加 `<style>` / `<script>` 完全允许——只要不覆盖平台变量和框架类名。

## 执行机制（约束如何落地）

| 强度 | 机制 | 管什么 |
|------|------|--------|
| **拒收**（server 400） | `POST /api/reports` 提交校验 | 裸 `<table>`；`cmp-table` 无 `cmp-verdict`；弃用类名（`.ladder-*` / `.quote-block` / `.concern-box` / `.phase`） |
| **提醒**（响应 warnings） | `validate_content` 软检查 | figure 缺图题/图注；AI 腔词；emoji；mermaid 无装裱。只提醒不拒收，agent 自觉修订 |
| **兜底**（模板 CSS） | 漏网裸表格按 data-table 渲染 | 防御纵深：即使绕过校验也不裸奔 |
| **规则**（本文件 + /api/guide） | agent 自觉 + review | 形态判定、必答问题、颜色语义、图题图注 |
| **结构**（黄金结构） | agent 自觉 | 章节顺序（见 AGENT-GUIDE.md） |

**为什么只拒收这两条？** 门禁越少越能守住。裸表格和"无结论对比"是已发生的真实事故，且机器可判定（正则即可）。形态判定、颜色语义这类需要理解内容的规则，机器判不准，强行校验只会制造误伤——留给规则和 review。

## 常见内容速查

| 我要表达…… | 用 | 收尾 |
|-------------|-----|------|
| A vs B vs C 选谁 | `cmp-table` + 推荐列 | `怎么选 · VERDICT` |
| 一组参数/配置/数据 | `data-table` | 无 |
| 某指标随时间变化 | 自由区图表 + `figure` 装裱 | 图注写"所以呢" |
| 架构/流程示意 | 自由区 SVG/图 + `figure` 装裱 | 图注写"关键在哪" |
| 先做 A 再做 B | `steps` | — |
| 一句话立场/引述 | `blockquote` | — |
| 小心踩坑 | `callout warn` | — |
| 三个并列特性 | `card` × 3 | — |

## 组件模板片段

### 图（新增）

```html
<figure class="figure">
  <!-- 框里随便放：img / svg / canvas / 图表库容器 / 交互 demo -->
  <img src="adoption-curve.svg" alt="采用率曲线">
  <figcaption class="fig-cap">图 1 · 2024–2026 向量数据库采用率</figcaption>
  <p class="fig-note">增长在 2025 下半年放缓——选型窗口正在关闭，现在不决定，之后就是存量迁移问题。</p>
</figure>
```

### 对比（已有，重申）

```html
<div class="cmp">
  <table class="cmp-table">
    <thead><tr>
      <th>维度</th>
      <th class="rec">选项 A<span class="cmp-rec-tag">推荐</span></th>
      <th>选项 B</th>
    </tr></thead>
    <tbody>
      <tr><td class="dim">关键能力</td>
          <td class="rec"><span class="cmp-v"><span class="g">✓ 原生支持</span></span></td>
          <td><span class="cmp-v"><span class="r">✗ 需自建</span></span></td></tr>
    </tbody>
  </table>
  <div class="cmp-verdict">
    <span class="vk">怎么选 · VERDICT</span>
    要 X 就选 A；要 Y 就选 B。两者不是替代关系——……
  </div>
</div>
```

# 叙事原则 —— 这本书的宪法

> 模板可以换，逻辑不能换。本文档定义一切模板必须体现的不变量；
> 模板是这些不变量在某类文档上的框架实现。

## 0. 元原则：类型 → 目的 → 叙事

文档有类型，类型有目的，目的决定叙事。没有放之四海皆准的最优框架，
只有普遍有效的逻辑。觉得默认模板装不下你的文档时，先回答：
这份文档的类型是什么？读者读完要做什么决定或获得什么？
答案决定框架该怎么搭——而不是反过来让内容迁就框架。

这条元原则本身也是契约条目（ID：`type-determines-narrative`）：
任何模板都要先说清它服务什么类型、读者读完要做什么，框架才算有了根。

## 1. 不变量（所有模板必须体现）

不变量不是审美偏好，而是读者心理的必然要求——换一类文档、换一个读者，
这些要求依然成立，所以它们不随模板改变。

1. **读者的关切先于细节**（`why-first`）——读者关心"帮我解决什么"，不是"你做了什么"。
   开篇必须回答"我为什么要读这个"。技术报告把痛点放前面；
   执行摘要把结论放前面——决策者的关切就是结论，结论先行正是它的 why-first。
   关切没被回答之前，读者没有耐心给细节。
2. **决策必答三问**（`three-questions`）——解决什么场景的什么问题？为什么是它而非替代？不这么做会怎样？
   读者批准一个方案，前提是信它解决了真问题、选择有依据、不动手有代价；
   三问缺一，批准就缺理由。
3. **主张配证据**（`evidence-for-claims`）——数据、场景、引用，至少其一。
   没有证据的判断是观点，不是研究。研究区别于观点的，正是可被检验的证据。
4. **技术类必须场景演练**（`scenario-exercise`）——小数据集、逐步计算、类比。
   抽象机制人人会复述，能否迁移到自己的场景才决定读者是否真懂。
   血泪教训："没有一个具体的例子和场景，我还是无法理解他的方式。"
5. **对比必有结论**（`verdict-on-comparison`）——回答"选谁"的内容必须以"怎么选 · VERDICT"收尾。
   读者做对比是为了选型；摆完维度不给结论，是把决策的活又丢回给读者。
6. **图必有图注**（`figure-caption`）——图题编号 + 图注回答"所以呢"。只贴图不解释 = 不合格。
   图省下的是解释成本；不写"所以呢"，省下的成本又让读者自己付回去。

## 2. 变量（模板实现的）

章节划分、大标题顺序、脚手架、阅读节奏——框架自由，但必须可从不变量推出：
**一个模板的框架 = 不变量针对某类文档的排布方式。**
大标题的顺序不是审美选择，是叙事逻辑的物化：先讲什么后讲什么，
决定了读者在每一屏是否已经具备理解下一屏的前提。

## 3. 契约条目（manifest 引用本表 ID）

模板 manifest 的 `narrative_contract` 字段引用下表 ID。ID 是机器校验的词表，
字符串逐字固定；新增不变量即新增一行，不改旧 ID。

| ID | 不变量 | 契约（模板必须体现） |
|----|--------|----------------------|
| `type-determines-narrative` | 元原则：类型 → 目的 → 叙事 | 模板声明它服务的文档类型与读者目的，框架由目的推出 |
| `why-first` | 读者的关切先于细节 | 开篇回答"为什么读"；决策类以结论开篇 |
| `three-questions` | 决策必答三问 | 每个技术决策回答：解决什么 / 为何是它 / 不这么做会怎样 |
| `evidence-for-claims` | 主张配证据 | 判断附数据、场景或引用，至少其一 |
| `scenario-exercise` | 技术类必须场景演练 | 小数据集 + 逐步计算 + 类比 |
| `verdict-on-comparison` | 对比必有结论 | 回答"选谁"以"怎么选 · VERDICT"收尾 |
| `figure-caption` | 图必有图注 | 图题编号 + 图注回答"所以呢" |

## 4. 模板与宪法的关系

- **book（默认）**：技术深度研究的逐章长读。不变量 → 黄金结构五章
  （定位 → 痛点/为什么 → 方案 → 细节验证 → 结论）+ 组件硬门禁。
- **brief**：结论先行的决策简报。why-first 体现为 TL;DR 开篇——
  读者 3 分钟内拿到结论与建议，依据与风险后置供查证。
- **创建新模板** = 论证"现有框架为何承载不了这个目的"（rationale）
  + 声明新框架体现哪些不变量（narrative_contract）+ 大标题顺序的叙事理由。
- **视觉语言不可谈判**：调色板 / 字体 / 组件库由平台拥有（book-style.css），
  模板只排布结构。换框架不换品味，"书"才不会碎成 N 种风格。
